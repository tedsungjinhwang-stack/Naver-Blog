# 이미지 소싱 원칙 (저작권 + 네이버 최적화)

> 결론: **남의 이미지를 긁어오지 않는다. 직접 만들거나, 라이선스가 명확한 것만 쓴다.**
> 이유는 두 가지 — 저작권 리스크, 그리고 펌 이미지가 많으면 유사문서/저품질 판정에 불리하다.

## 1. 절대 하지 말 것

- 구글/네이버 이미지 검색 결과를 그대로 저장해서 사용
- 언론사 사진·기사 캡처 무단 사용 (신고 대상)
- 타 블로그 이미지 퍼오기 (유사문서 감점 + 저작권)
- 워터마크 제거·크롭 후 사용
- 출처만 적으면 괜찮다는 오해 — **출처 표기는 이용 허락이 아니다**

## 2. 권장 순서 (위에서부터 우선)

1. **직접 만든 차트·도식** — 가장 안전하고 D.I.A.+ 고유성 점수에 가장 유리하다.
   - `tools/make_charts.py` 참고. 공개 수치를 근거로 matplotlib으로 직접 그린다.
   - 한글 폰트: `apt-get install fonts-nanum` 후 NanumGothic 사용.
2. **직접 촬영한 사진** — 통장 화면, 계산기, 손계산 메모, 현장 사진 등.
   - 개인정보(계좌번호·이름·주소)는 반드시 가린다.
3. **본인이 조작한 화면 캡처** — 내가 접속해서 조회한 결과 화면.
   - 예: 한국은행 ECOS, KRX, 국토교통부 실거래가, 대출 계산기 결과.
   - 공공기관 자료는 대부분 **공공누리** 적용이나, 유형(제1~4유형)에 따라 조건이
     다르므로 해당 페이지의 이용조건을 확인하고 출처를 표기한다.
4. **라이선스가 명확한 무료 이미지** — 사용 전 각 사이트의 현재 약관을 직접 확인할 것.
   - 예: Unsplash, Pexels, Pixabay 등. 상업적 이용/수정 가능 여부, 인물 초상권,
     로고·상표가 찍힌 사진인지 확인한다.
   - 다만 이런 스톡 사진은 다른 블로그도 많이 쓰므로 고유성 측면에선 순위가 낮다.
5. **AI 생성 이미지** — 표지/썸네일 정도로 제한적으로.
   - 경제·투자 글에서 본문 근거로 쓰기엔 부적합하다. 숫자는 반드시 실제 데이터로.

## 3. 네이버 관점 체크리스트

- [ ] 이미지 5장 이상 (체류시간·완독률에 유리)
- [ ] 그중 **직접 제작/촬영 이미지가 과반**인가
- [ ] 각 이미지에 대체텍스트(alt) 입력 — 접근성 + 검색 이해도
- [ ] 첫 번째 이미지는 대표 이미지로 쓰이므로 내용을 대표할 것
- [ ] 파일명을 의미 있게 (kospi_retracement.png 처럼)
- [ ] 사진에 개인정보·타인 얼굴·상표 노출 없는지 확인
- [ ] 협찬 이미지면 대가성 고지와 함께 사용

## 4. 니치별 '직접 만들기' 아이디어

| 니치 | 만들기 좋은 이미지 |
| --- | --- |
| 경제 | 금리·물가 추이 차트, 손계산 노트, ECOS 조회 화면 캡처 |
| 투자 | 되돌림·지지선 도식, 비중 도넛, 수익률 계산표 |
| 부업 | 실제 정산 화면(금액 외 개인정보 가림), 시간당 수익 계산표, 작업 환경 사진 |
| 부동산 | 실거래가 조회 캡처, 단지 배치도 스케치, 대출 시뮬레이션 결과, 현장 답사 사진 |

## 5. 차트 생성 사용법

```bash
pip install matplotlib
apt-get install -y fonts-nanum      # 한글 깨짐 방지
python3 tools/make_charts.py output/images
```

`tools/make_charts.py` 상단 `CFG` 값을 발행 시점 수치로 갱신한 뒤 실행한다.
새 주제용 차트가 필요하면 함수를 하나 추가하는 방식으로 확장한다.
